## 一、动机

构画的「今天」现在靠 `almTodayAnchor()`（返回 `{month,day}`）的 fallback 链（钉住手动锚 → 柏宝书 → memory → lines）糊推，不够准也没有小时/年。要让点/线/面/历/暗账都算得准「距今多久」，得有一个**跟着剧情走**的坚固时间源。

用户定的方向：**强制注入提示词，让主楼 AI 每楼产出时间戳，我们读回**。通法通解，不为「装没装柏宝书」做特殊 fallback（同时用构画+柏宝书的用户仅三五个）。

## 二、调研 ST-BaiBai-Book（柏宝书·记忆插件·同机 third-party）

**只学方法论、指路不抄原文**（用户明确：不能照抄它的提示词，按我们实际情况自写）。
参考来源（只读学习，不改、不复制文本）：`ST-BaiBai-Book/src/memory/{timeTag,timeRel,inject,prompts}.ts`。

它实际的做法（**注意：它只打绝对时间、没打增量，照样从不漏**）：
1. **起止双标签**：每楼正文最前 `<bbs_start>` + 最后 `<bbs_end>`，各一个完整时间。理由：一楼时间跨度可能大，单快照取不准 → 要起点+终点两个界。
2. **标签留正文、只在显示层用 ST 正则隐藏，绝不真删**：这是「从不漏」的命门——下楼主模型看得见上楼 `<bbs_end>`，自然以它为基准往前推（增量在模型脑内、输出成绝对值）。真删=下楼失基准=时间失同步。
3. **往回扫 + 多层兜底**（`latestStoryTime`）：读「当前时间」从 chat 末尾往前扫取第一条可解析的（end 优先）；某楼漏/坏 → 上一条顶上；正文全无标签（老聊天）→ 退回该楼摘要叶子里的时间。「从不漏」实为「漏了也不崩」，非靠重试硬凑。
4. **强制完整格式**（`RULE_COMPLETE_TIME_ANCHOR`）：`YYYY/M/D HH:mm`，年份不许省（否则跨年天数差、周几都算不了）。粒度到分钟。
5. **相对时间独立算**（`timeRel.ts`，移植自 Horae）：绝对→「昨天/3天前」前缀；数字历精确算、架空历仅同月可算、解析不出不加前缀。信条「宁可不标，绝不标错」（与构画 almTodayAnchor fallback 哲学同源）。
6. **注入**：`inject.ts` 走 `setExtensionPrompt`，IN_CHAT + **depth=0** + SYSTEM role，且**仅在开了自动摘要时**才注入 timeTag 提示词。

**从它提示词里提炼的三个套路**（这些是通用方法论、可吸收；措辞/示例/标签名是它的、不搬）：
- 明说「这是给记忆系统读的锚点，请务必每次都输出」+ 拔高到「系统强制」→ 比干要求格式更让主模型每楼照办。
- 「以上一段结束时间为基准推进」→ 靠标签留正文实现的脑内增量。
- 「开篇自行设定、不算编造、但禁止用『某天』敷衍」→ 预先拆掉主模型「不知道几点所以写模糊词」的退路。这条是「从不漏」的提示词侧根源。

## 三、构画自己的方案（借思路、全自写）

- **载体：HTML 注释** `<!-- -->`。酒馆天然不渲染 → **省掉柏宝书那条显示层隐藏正则**。但「注释必须留在 `message.mes` 里让下楼继承基准」这条命门照做（换载体不换机制）。具体注释格式待定，自拟（别用 bbs_ 前缀）。
- **起止双界**：吸收——一楼是一段区间不是一个点，起+止两个时间戳。
- **粒度到小时**（分钟不做）：柏宝书到分钟是超集，我们取小时即可。
- **数据结构扩容**（**工作量大头·分步来**）：`almTodayAnchor` 从 `{month,day}` → `{year?, month, day, hour}`。牵动点/线/面/历**所有查「今天」的地方**，地基改造。
  - **年份底层存**（为算跨年天数差），但 **UI 对用户可选择不显示**（尊重构画「历不挂年：年太模糊、绝大多数卡不是现实年份」的现有理念）。数据层与显示层分离。
- **读取**：照「往回扫 + fallback」自写；单楼失败不崩，最后退回现有 almTodayAnchor 链。
- **提示词**：全自写，贴合构画实际（HTML 注释载体、小时粒度、自定义历法月名如「霜月」）。吸收三套路，措辞/示例原创。
- **相对时间**：参考 timeRel 思路自写「距今 X 天/时」，数字历精确、架空历同月可算、解析不出不加前缀。
- **注入方向辨析**：这个「让主模型**产出**时间戳」的指令与暗账④「喂**结论**给主模型」方向相反 → depth 浅（0 或 1）贴最近、强约束合适，届时定。
- **开关**：常驻注入每楼给主模型多吃一小段提示词 = 对不用的人是负担 → 需独立开关（跟历总开关的统辖关系待定）。

## 四、与构画现有坑的交叉（开工前先记，别重踩）

## 六、实施进展（2026-08-08 · 第一片落代码）

**分支** `feature/story-clock`（从 master 2.7.0=05d4cfd 切）。**未提交**（照「验证前不提交」）。

**格式定案（用户 2026-08-08 拍板）**：
- 载体 HTML 注释，前缀 **`SDC`**（取自 repo 名 SevenDaysCal；比 `sp`/`TimeCalc` 更生僻防撞）。
- 文头 `<!-- SDC-start <时间> -->` + 文尾 `<!-- SDC-end <时间> -->`，**首尾两界够了**；中间戳留作后续可选片。
- **默认开**（用户：这是全插件时间地基，值得常驻）。

**第一片范围（只做注入+回读+只读显示，刻意不碰数据形状）**：
1. **注入** `refreshStoryClockInjection()`：照 `refreshLinesInjection` 套路，`SDC_CLOCK_INJECT_KEY='sdc_story_clock'`，**depth=0** / IN_CHAT / SYSTEM（柏宝书 timeTag 也是 depth0；「让主模型产出戳」要贴身）。双闸：`injectEnabled()`（含插件总关）+ `storyClockEnabled()`。提示词 `buildStoryClockPrompt()` **全自写**（吸收柏宝书三套路：拔高系统强制/以上楼 end 为基准/禁「某天」敷衍；措辞示例标签名原创，绝不照搬）。
   - 缝进 4 处 refresh 点：`backfillLinesInlineBlocks`(首屏/切chat/主开关)、`CHAT_CHANGED`、插件总开关 on 分支、注入总闸 handler；插件总关 off 分支显式清空 `SDC_CLOCK_INJECT_KEY`。
2. **回读** `parseStoryClock(mes)`（首尾双正则 `SDC_START_RE`/`SDC_END_RE`，宽松容错、lazy 不跨戳吞）+ `latestStoryClock()`（从末楼往回扫 `ALM_CHAT_SCAN_LIMIT=40`，end 优先，漏了继续找、全无返 null）。node 单测 5 例全过（双戳/单起/单尾/无戳/多行）。
3. **只读显示** `storyClockBarHtml()`：历面板今天条下方一行「⏰剧情时刻：起 → 止」。**本片只回显原文、不解析成结构、不接 almTodayAnchor**。CSS `.sp-alm-clock*`（照 `.sp-alm-today` 略素）。
4. **开关**：设置面板新增独立段「剧情时钟」（在 历·点 段与 棱 段之间），`sp-storyclock-enabled`，默认勾选；handler 存 `storyClockEnabled` + refresh + 若在历面板则重渲。

**关键旋钮/事实**（下次排查先看）：
- `storyClockEnabled` 默认 **true**（DEFAULT_SETTINGS）。总闸 `injectEnabled` 关则不注入（与线/面一致）。
- 显示行只 gate `storyClockEnabled()`、**不** gate injectEnabled——显示=chat 里的实况，与「当前是否在注入」解耦（更稳）。
- `latestStoryClock` 引用的 `ALM_CHAT_SCAN_LIMIT` 定义在 ~8290、函数在 ~1878：模块级 const + 调用时求值，无 TDZ 问题（面板打开才调，远晚于模块加载）。
